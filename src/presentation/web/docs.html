Quickstart

Steps 1 to 4 also work in the dashboard.

  1. Create an account

    Email only. You get an owner token (uk_…), shown once.

    curl -s <origin>/api/signup -H "content-type: application/json" \
  -d '{"email":"you@example.com"}'

  2. Verify

    In the dashboard, click Verify with test details. The sandbox approves made-up details and issues your card. Own details must be unique each time.

  3. Add money

    Send test USDC to your deposit address (networks), or click Simulate deposit. $1.00 or more moves onto the card automatically.

  4. Create an agent

    Set a per-payment and a daily limit, then give it a balance. Copy its token (ak_…), shown once.

    curl -s <origin>/api/me/agents -H "Authorization: Bearer uk_…" \
  -H "content-type: application/json" \
  -d '{"name":"research-bot","perTransactionCents":2000,"dailyCents":5000}'

curl -s <origin>/api/me/agents/a_1234abcd/fund -H "Authorization: Bearer uk_…" \
  -H "content-type: application/json" -d '{"amountCents":1000}'

  5. Connect the agent

    Three ways, same token and rules.

    A. Claude Code (MCP over HTTP)

    claude mcp add --transport http agent-cards <origin>/mcp \
  --header "Authorization: Bearer ak_…"

    B. MCP over stdio

    For clients that launch a local process. Set cwd to the project.

    {
  "mcpServers": {
    "agent-cards": {
      "command": "node",
      "args": ["--import", "tsx", "src/startMcpStdio.ts"],
      "cwd": "/path/to/agent-cards",
      "env": { "AGENT_CARDS_URL": "<origin>", "AGENT_CARDS_TOKEN": "ak_…" }
    }
  }
}

    C. Plain HTTP

    curl -s <origin>/agent/v1/pay -H "Authorization: Bearer ak_…" \
  -H "content-type: application/json" \
  -d '{"amountCents":500,"merchant":"Example API","mcc":"5734","idempotencyKey":"order-1"}'

Concepts

Owner

You. Sign up with an email, pass KYC once. No password; you hold a uk_ token.

Card

One Visa card per owner, issued by Miden. Your tier sets its limits.

Agent wallet

A sub-balance of the card with a per-payment limit, a daily limit and optional merchant category codes (MCC). Limits can't exceed the card's. Agents have no KYC, never see card details, and use an ak_ token.

Funding

USDC lands in a holding balance, then tops up the card (minimum $1.00). Give moves money to an agent, take back returns it, and revoke disables the token and returns the balance.

Authentication

Send a bearer token on every call except sign-up.

TokenPrefixUsed for
Owneruk_/api/me…. Issued at sign-up; rotate with POST /api/me/token.
Agentak_/agent/v1/… and /mcp. Issued per agent.
Authorization: Bearer ak_…
  • Tokens are shown once and stored as SHA-256 hashes. Lost one? Rotate it or create a new agent.
  • POST needs content-type: application/json (else 415) and, from a browser, this server's own Origin.
  • Only 127.0.0.1 or localhost Host headers are accepted (else 421), which blocks DNS rebinding.

Agent REST API

Base URL <origin>/agent/v1. Agent token. Amounts are integer US cents.

Get wallet

GET/agent/v1/wallet

Balance, limits and today's remaining allowance.

curl -s <origin>/agent/v1/wallet -H "Authorization: Bearer ak_…"
{
  "agentId": "a_1234abcd",
  "name": "research-bot",
  "currency": "USD",
  "balanceCents": 1000,
  "limits": { "perTransactionCents": 2000, "dailyCents": 5000, "allowedMccs": null },
  "spentTodayCents": 0,
  "remainingTodayCents": 5000
}

remainingTodayCents ignores balance, so a payment can still fail for lack of funds.

List transactions

GET/agent/v1/transactions?limit=20

Recent payments, newest first. limit: 1 to 100 (default 20).

curl -s "<origin>/agent/v1/transactions?limit=5" -H "Authorization: Bearer ak_…"
[
  {
    "spendId": "sp_9f2c41d0aa11b2c3d4e5",
    "amountCents": 500,
    "merchant": "Example API",
    "mcc": "5734",
    "status": "approved",
    "reason": null,
    "createdAt": "2026-10-19T15:08:40.768Z"
  }
]

Pay a merchant

POST/agent/v1/pay

Checks the agent's rules and balance, then charges the card. A rule break is recorded as declined; nothing is charged.

FieldTypeDescription
amountCentsintegerRequired. Positive whole cents.
merchantstringRequired. Up to 80 characters.
mccstringOptional 4-digit category code. Needed if the agent has an allow-list.
idempotencyKeystringOptional, up to 100 characters. Always send one (why).
curl -s -X POST <origin>/agent/v1/pay \
  -H "Authorization: Bearer ak_…" -H "content-type: application/json" \
  -d '{"amountCents":1250,"merchant":"Example API","mcc":"5734","idempotencyKey":"order-1"}'
{
  "spendId": "sp_9f2c41d0aa11b2c3d4e5",
  "amountCents": 1250,
  "merchant": "Example API",
  "mcc": "5734",
  "status": "approved",
  "reason": null,
  "createdAt": "2026-10-19T15:08:40.768Z"
}

A decline is still HTTP 200 with "status": "declined" and a reason. Check status (statuses).

MCP

POST <origin>/mcp. Stateless streamable HTTP, agent token. For local-process clients use the stdio bridge, which won't send a token over plain http to non-localhost hosts.

ToolArgumentsReturns
get_walletnoneThe wallet (cents).
payamount_usd (number, at most 2 decimals), merchant, mcc?, idempotency_key?The payment object. Dollars in, cents out.
list_transactionslimit? (1 to 100)Array of payments, newest first.

The server instructs the model to check get_wallet first, use a fresh idempotency_key per purchase, and never re-pay while processing.

{
  "amount_usd": 12.50,
  "merchant": "Example API",
  "mcc": "5734",
  "idempotency_key": "order-1"
}

Owner API

Base URL <origin>/api. Owner token, except signup. Integer cents. The dashboard uses these calls.

EndpointBodyWhat it does
POST /api/signup{ email }201 with { userId, token }. Duplicate email: 409.
GET /api/meKYC status, tier, card, balances, deposit address, deposits, top-ups, agents.
POST /api/me/tokenReplaces your owner token.
POST /api/me/kycidentity fieldsSubmits Card KYC to Miden: firstName, lastName, dateOfBirth (YYYY-MM-DD), idType, idNumber, phone, email, idFrontImage (PNG/JPEG data URI), address. Not stored.
POST /api/me/refreshRe-checks KYC and issues the card once approved (also runs every 5 s).
POST /api/me/simulate-deposit{ amountCents }Sandbox: fake deposit, up to $1,000. 403 if off.
POST /api/me/agents{ name, perTransactionCents, dailyCents, allowedMccs? }Creates an agent. Returns { agentId, name, policy, token } (token shown once). allowedMccs: list or comma-separated 4-digit codes.
POST /api/me/agents/{id}/fund{ amountCents }Card to agent. 409 if the card lacks money.
POST /api/me/agents/{id}/reclaim{ amountCents }Agent to card. 409 if the agent holds less.
POST /api/me/agents/{id}/limits{ perTransactionCents, dailyCents, allowedMccs? }Updates rules, within the card's limits.
POST /api/me/agents/{id}/revokeDisables the token; balance returns to the card.

Payments & statuses

StatusMeaningMoneyWhat to do
approvedThe card network accepted it.Spent.Done.
declinedBroke a rule: limit, category or balance. reason says which.Not charged.Fix it, retry with a new key.
voidedThe card network refused it.Reversed.Try another merchant.
processingNo answer from the network yet.Held.Do not pay again. Poll transactions; it settles itself (checked at about 1 minute, flagged at 10).

Idempotency

Retry the same purchase with the same idempotencyKey (REST) or idempotency_key (MCP) and you get the original result, not a second charge.

  • Same key, same payment: the first result, even if declined. New attempt, new key.
  • Same key, different amount, merchant or MCC: 409.
  • Same key while the first call is running: 409. Retry shortly.
  • No key: every call is a new payment, so a retry after a timeout can pay twice.
  • Keys are per agent.

Errors

Errors are JSON: { "error": "message" }.

StatusMeaningTypical cause
400Bad requestInvalid field, amount not positive whole cents, MCC not 4 digits, limit above the card's.
401UnauthorizedMissing, wrong or revoked token, or uk_ vs ak_ mixed up.
403ForbiddenCross-origin request, or simulated deposits off.
404Not foundUnknown path, agent or card.
409ConflictIdempotency clash, revoked agent, not enough money to move, KYC already done, email taken.
413Too largeBody over 2 MB.
415Wrong content typeA POST without content-type: application/json.
421MisdirectedUnexpected Host header.
422UnprocessableMiden rejected the KYC submission.
500Internal errorOurs. Retry with the same key.

Sandbox notes & FAQ

Is this real money?

No. Miden sandbox card, simulated authorizations, testnet USDC.

Why is my Miden balance $1.00 higher than my ledger?

Miden opens every card with a $1.00 minimum.

Can an agent see the card number?

No. Agents only call pay.

A payment is stuck on processing.

The money is held, not lost. It settles on its own. Don't retry with a new key.

I lost an agent token.

Revoke the agent (its balance returns to the card) and create a new one.

Can I reach this from another machine?

No. It binds to localhost and rejects other Host headers.
