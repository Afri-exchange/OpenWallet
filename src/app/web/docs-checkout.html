Agent Cards Checkout

Let AI agents pay you. You set the price; the agent pays from the wallet its owner funded, inside the limits its owner set. No card details ever reach the agent or you.

Sandbox only. The agent's card is charged through Miden's sandbox purchase simulator, and payouts are testnet USDC. Examples use this server's address (<origin>). The SDK is @agent-cards/checkout (sdk/checkout in the repo): no dependencies, not on npm yet, so import it by path.

Quickstart

  1. Get sandbox keys

    With the service running, one command in the repo creates a merchant secret key (mk_…), a funded test agent token (ak_…) and pays a $1 test checkout. Keys go to the git-ignored .env.sandbox-keys; nothing secret is printed.

    scripts/sandbox-up.sh
node --import tsx scripts/dev-quickstart.ts

    Or create just a merchant by hand. The secret key is shown once; keep it server side.

    curl -s <origin>/merchant/v1/signup -H "content-type: application/json" \
  -d '{"name":"Acme API","email":"billing@acme.example","mcc":"5734"}'

  2. Create a checkout

    import { AgentCardsCheckout } from "./sdk/checkout/src/index.ts";

const checkout = new AgentCardsCheckout({
  baseUrl: process.env.AGENT_CARDS_URL!,
  secretKey: process.env.AGENT_CARDS_SECRET_KEY!,
});
const c = await checkout.createCheckout({
  amountCents: 1299,
  description: "Pro plan, 1 month",
  reference: "order_8812",
  idempotencyKey: "order_8812",
});
console.log(c.checkoutUrl);   // hand this (or c.checkoutId) to the agent

  3. Let an agent pay it

    A real agent calls the MCP tool pay_checkout. To try it without one, use the test agent token:

    const agent = new AgentCardsAgent({ baseUrl, token: process.env.AGENT_CARDS_AGENT_TOKEN! });
await agent.payCheckout(c.checkoutId, { maxAmountCents: 1299 });

  4. Fulfil when paid

    const done = await checkout.waitForPayment(c.checkoutId, { timeoutMs: 120_000 });
if (done.status === "paid") fulfil(done.reference);

A complete merchant (cart, server-side pricing, order page, polling, cancel) is in examples/shop. Run it with node --env-file=../../.env.sandbox-keys --import tsx server.ts.

How it works

  1. Your server creates a checkout with your secret key and gets a checkoutId (cs_…) and a checkoutUrl (<origin>/pay/cs_…).
  2. You hand either one to the agent: put it on the page, return it from your API, or say it in a chat.
  3. The agent calls pay_checkout (MCP) or POST /agent/v1/checkouts/<id>/pay. Its owner's per-payment, daily and merchant-category limits and its balance all apply.
  4. You fulfil the order once the checkout reads paid.

A checkout is paid at most once. If a payment is declined (limits, balance, or the card network), the checkout stays open and the agent can try again later.

Agent Cards is the merchant of record: each paid checkout is credited to your balance with us, and you are paid out from it. Neither you nor the agent ever sees card details.

Checkout statuses

StatusMeaningWhat to do
openWaiting for an agent to pay.Wait, or cancel.
processingAn agent's payment is under way, or the card network's answer is late and it settles in the background.Do not fulfil yet.
paidPaid.Fulfil the order.
canceledYou canceled it (open checkouts only).Nothing.
expiredNobody paid in time (default 30 minutes).Create a new one.

Merchant SDK

Server side only. AgentCardsCheckout methods:

MethodWhat it does
AgentCardsCheckout.signup(opts, {name, email, mcc?})Creates a merchant account; returns the secret key once.
createCheckout(params)Fixed-price checkout. Params: amountCents, description, reference? (your order id, echoed back), mcc?, expiresInSeconds?, metadata? (yours only, never shown to agents), idempotencyKey?.
retrieveCheckout(id)The source of truth for whether you were paid.
waitForPayment(id, {timeoutMs?, intervalMs?, signal?})Polls until paid, canceled or expired. If time runs out it returns the checkout as it is: check status.
listCheckouts({limit?}), cancelCheckout(id)Newest first; cancel works on open only.
me(), rotateKey()Your profile; replace the secret key (the old one stops at once).
balance(), setPayoutAddress(a), requestPayout(p), listPayouts()See Getting paid.

On your page

Server-rendered helpers, no script needed:

html.head += checkoutMetaTag(c);   // lets an agent reading the page find the checkout
html.body += checkoutButton(c);    // "Pay $12.99 with Agent Card"

Fulfilling orders

  • Fulfil only when status === "paid" from retrieveCheckout or waitForPayment, and only once. Check underReview is empty too.
  • Price on your server; never take an amount from the browser.
  • Webhooks are not available yet: poll.

Getting paid

Each paid checkout is credited to your balance with us. Payouts are USDC on Base Sepolia (testnet) for now; bank transfers will follow.

await checkout.setPayoutAddress("0xYourWallet…");   // once; a new address waits before it can be paid
const { availableCents } = await checkout.balance();
const payout = await checkout.requestPayout({ amountCents: availableCents, idempotencyKey: "payout-2026-10" });
// payout.status: "requested" → "sending" (payout.txHash) → "sent", or "failed" (money returns to your balance)
  • A payout is reserved from your balance the moment you ask, so it can never be paid twice or exceed what you are owed (409 if it would).
  • It goes to the address you had when you asked; changing the address later does not redirect it.
  • A new address can be paid only after a waiting period (me().payoutAddressUsableFrom; 10 minutes in the sandbox), so a stolen secret key cannot send your money elsewhere at once.

Agent side

With the Agent Cards MCP server connected (see Agent Cards · MCP), an agent has two checkout tools:

ToolArgumentsReturns
get_checkoutcheckout_idMerchant, description, price and status.
pay_checkoutcheckout_idPays at the merchant's price. Calling it again returns the first result.

Agents without MCP can use AgentCardsAgent (getCheckout accepts an id or the link; payCheckout(id, { maxAmountCents }) refuses a dearer checkout without charging) or the REST endpoints below. The payment is an ordinary agent payment, so the agent's limits, merchant-category allow-list and balance all apply (see Payments & statuses).

Every POST needs content-type: application/json. Amounts are US cents. mk_ = merchant secret key, ak_ = agent token, sent as Authorization: Bearer ….

Idempotency

  • Creating: send an idempotencyKey on createCheckout (your order id works). A retry returns the same checkout instead of making a second one.
  • Paying: a checkout is paid at most once. Calling pay_checkout again returns the first result, and the same attempt is never charged twice. A declined attempt can be retried later as a new attempt.
  • Payouts: send an idempotencyKey on requestPayout so a retry never asks twice.

Errors

Errors are JSON: { "error": "message" }. The SDK throws AgentCardsError with status and message. See also Agent Cards · Errors.

StatusTypical cause here
400Missing or invalid field, amount not a positive whole number of cents.
401Missing, wrong, rotated or revoked key; or the wrong kind (mk_ vs ak_).
404Unknown checkout or payout.
409Cancel on a checkout that is not open; idempotency key reused for a different request; payout over the balance, with no address, or during an address change's wait.

A declined payment is not an HTTP error: payCheckout returns a payment with status: "declined" and a reason, and the checkout stays open.

Security

  • The secret key (mk_…) stays on your server. Never ship it to a browser or an agent. Rotate it with rotateKey() if it leaks.
  • The SDK refuses to send a key over plain http to anything but localhost.
  • Pass maxAmountCents from the agent so a checkout whose price changed is refused without charging.
  • Never trust the browser's idea of the price or of "paid": re-read the checkout from your server.

Not yet

  • Bank payouts and mainnet USDC. Testnet USDC only for now.
  • Webhooks. Poll with retrieveCheckout or waitForPayment.
  • Refunds. There is no refund API yet.
  • Real merchants. Merchant signup is unverified and the charge is Miden's sandbox simulator.
